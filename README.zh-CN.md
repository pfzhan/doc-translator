# Doc Translator

[English](README.md) | 简体中文

网页版文档翻译工具，支持 EPUB、MOBI / AZW3、PDF、Word（.docx）、HTML、Markdown 和字幕（SRT、VTT、ASS），可输出双语对照或仅译文。

## 启动

需要 Python 3.12 或更高版本。macOS 自带的 `python3` 是 3.9，可用 `brew install python@3.12` 安装；Linux 可用发行版自带的 3.12（如 Ubuntu 24.04），或用 pyenv 安装。默认的 `python3` 低于 3.12 时，把下面第一条命令里的 `python3` 换成 `python3.12`。Debian、Ubuntu 上还要先安装 `python3-venv`。

macOS、Linux 上执行：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8765
```

启动后打开 http://127.0.0.1:8765 。

关闭终端后服务也会退出。需要在后台一直运行时，用 `nohup .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8765 > server.log 2>&1 &` 启动，输出写在 `server.log`。

服务只接受 `127.0.0.1`、`localhost` 等本机地址的访问。需要通过局域网 IP 或域名访问时，用环境变量 `ALLOWED_HOSTS` 追加（逗号分隔），例如 `ALLOWED_HOSTS=192.168.1.20 .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8765`。

## 翻译服务

在页面顶部的「翻译服务」中管理。同一类型可添加多个（不同的 Key、不同的模型或中转地址），每个服务可单独启用、设为默认、测试。

| 类型 | 接口 | 默认地址 |
| --- | --- | --- |
| 谷歌翻译 | 免费网页接口，无需 Key，量大可能被限流 | 内置 |
| OpenAI | Chat Completions | `https://api.openai.com/v1` |
| Claude | Anthropic Messages | `https://api.anthropic.com/v1` |
| Gemini | generateContent | `https://generativelanguage.googleapis.com/v1beta` |
| Grok | OpenAI 兼容 | `https://api.x.ai/v1` |
| OpenAI 兼容接口 | Chat Completions | 自行填写，如 DeepSeek、通义、Kimi、OpenRouter、Ollama |

每个服务可配置 API Key、名称、API 地址、模型（预置列表、自定义输入或从接口获取列表）。高级设置包含并发数、每批段落数和字符数、temperature、System Prompt 和 Prompt。

术语表在高级设置中维护，每行一条「原文 = 译文」。大模型服务默认还会在翻译前统计文档中反复出现的术语（多词短语、缩写、高频词），再用一次请求让模型结合文档领域确定译名，全文按该表翻译。每批只带上该批原文中出现的条目，手动填写的条目优先。生成的术语表随翻译缓存保存，继续翻译、重试和生成另一种版本时沿用同一张。如需省去这次请求，可在高级设置中关闭。

### 术语表库

「术语表」页按领域或系列书籍分别保存命名的术语表，存放在 `data/glossaries.json`，条目格式与翻译服务里的术语表相同（每行「原文 = 译文」）。提交文件时在翻译页勾选要用的术语表（可多选），所选术语表随记录保存，继续翻译、重试和生成另一种版本时沿用。

- 所选术语表追加在翻译服务自己的术语表之后，服务里的条目优先；与服务的术语表一样，每批只带上该批原文中出现的条目。术语表条目计入缓存键。修改术语表后，用到它的记录继续或重新翻译时按新的术语表重新翻译全部段落；生成另一种版本和清理缓存仍按上次翻译时的条目。记录用过的术语表被删除后，继续翻译时不再带这些条目。
- 「从 CSV / TSV 文件导入…」把文件前两列（原文、译文）追加到条目中，也接受带表头的文件和「原文 = 译文」格式的行；保存术语表后才生效。「导出 CSV」下载 UTF-8 文件，Excel 可直接打开。
- 接口为 `GET` / `POST /api/glossaries`、`PUT` / `DELETE /api/glossaries/{id}`、`POST /api/glossaries/import`（`{"text": ...}`）和 `GET /api/glossaries/{id}/export`。提交任务时 `glossary_ids` 表单字段可重复，传入术语表 id。

### 翻译记录

每次翻译都会保存一条记录（「记录」页；翻译页底部显示最近 3 条）。刷新页面或重启服务后记录仍在。翻译页可以一次选择或拖入多个文件，每个文件按相同的设置各提交一条记录；上传失败的文件列在按钮下方，并保持选中，原因排除后可以再次提交。任务完成或失败时，页面在前台显示提示，在后台发系统通知；第一次提交时浏览器会询问是否允许通知。通知只在 localhost、127.0.0.1 或 HTTPS 下可用，通过局域网 IP 以 HTTP 访问时只有页面内的提示。

- 记录和相关文件（原文件、译文、预览）只在两种情况下删除：在列表中手动删除，或超过保留时间。
- 保留时间在「记录」页顶部设置：7 天、30 天（默认）、90 天、1 年、永久保留或自定义天数，保存在 `data/settings.json` 的 `retention_days`（0 表示永久）。服务启动时检查一次，之后每小时检查一次。
- 同时翻译的任务数在「记录」页顶部设置（1 到 8 本，默认 2 本），保存在 `data/settings.json` 的 `max_jobs`。超出的任务显示「排队中」和队列位置，前面的任务完成、失败、暂停或删除后按提交顺序开始。排队中的任务可以「优先翻译」，移到队列最前，下一个空位就轮到它；正在翻译的任务不受影响。暂停的任务离开队列，继续翻译时排到队尾。排队的任务在开始时才按翻译服务当时的配置创建，排队期间换了模型或 Key 会生效；服务已被删除的任务轮到时直接失败，不影响后面的任务。
- 翻译中的任务可以「暂停」（列表和阅读器顶栏都有）。PDF 正在分析版面或写回译文时暂停，在当前页做完后停下。多个任务同时翻译时，列表上方会出现「全部暂停」。暂停的任务通过「继续翻译」或「全部继续」恢复，也可以「重译」。
- 继续翻译时按翻译服务的当前配置重新创建引擎。若暂停期间换了模型，缓存键随之变化，已翻译的段落不会复用，而是按新模型重新翻译；配置不变则直接复用。也可以在阅读器中换成其他翻译服务。
- 服务重启时未完成的任务标记为「已中断」，可以「继续翻译」；已暂停的任务重启后仍保持暂停。
- PDF 的版面分析结果按文件内容存在 `data/layout/<文件摘要>/` 下，同一份文件的几条记录共用。继续翻译、生成另一种版本、同一本书再传一次时，原文件、两个模型和程序都没变，就直接读回，不再逐页分析（几百页的书约省十分钟）；程序更新后重新分析。重译时勾选「全部重新翻译」，从版面分析做起。删除记录时，没有别的记录用同一份文件才一并删除。
- 公式检测模型和版面模型框出的框另存一份（同一目录里的 boxes.json）。程序更新、「全部重新翻译」后重新分析时，原文件和模型没变就读回这些框，只重跑规则：86 页的论文两个模型都开时，重新分析从 4 分半降到 20 多秒。
- 失败的任务可以「重试」。
- 记录页保留时间下方的「清理无用缓存…」清除没有记录用到的译文：网页翻译的译文，以及删除时没有清理缓存的旧记录留下的译文。记录用到的译文保留，继续翻译、生成另一种版本都不用重新请求。缓存开始记录归属之前（2026-10-31 以前）存下的译文无法区分，也会保留，对话框里会显示有多少条，缓存满了会自动淘汰。有任务正在翻译时不能清理。接口是 `GET` / `DELETE /api/cache/unused`。
- 生成的 PDF 和 EPUB 可以点「预览」，在浏览器新标签页中直接打开，不用下载。两种版本都已生成时，分别显示「预览译文」「预览双语」。PDF 用浏览器自带的阅读器；EPUB 由服务从文件里逐章取出，左侧是书的目录，可以上一章、下一章（也可按左右方向键），刷新后停在原来那一章。书里的脚本不会执行。
- 已完成的任务可以生成另一种版本（双语 ⇄ 仅译文）。该操作使用当时的模型和翻译缓存，只重新排版；缓存对不上（提示词变了，或文档分段变了）时会提示重新翻译，不会在本次请求中重译。

### 阅读器（边翻边预览）

文件提交后停留在翻译页，任务显示在「最近翻译」中。点「查看进度」或「阅读」进入全屏阅读器，译完一段显示一段。PDF 开始翻译前要分析版面，全部译完后要逐页写回，整本书各需一两分钟到几分钟，这两段时间任务和阅读器显示分析或写回到第几页。几个 PDF 任务同时进行时，分析版面和写回一次只做一个任务，其余任务显示「等待其他任务」，翻译仍可同时进行。PDF 按文本块预览：明显大于正文的短块，以及略大于正文的粗体短块，显示为小标题。加入预览功能之前的记录需重新翻译后才能打开。加密或没有文字的 PDF 会翻译失败，阅读器停在错误提示，不再轮询。

- 宽屏左右对照，窄屏上下排列，可切换「对照 / 译文 / 原文」；正文使用衬线字体，标题、列表、引用有各自的样式。
- 左侧大纲来自文档的章节标题，圆点表示该章进度（灰色未开始、蓝色翻译中、绿色已完成），标题译完后显示译文；窄屏下收进抽屉。
- 默认跟随翻译进度；手动滚动或点击大纲后暂停跟随，底部出现「跟随翻译进度」按钮。跳转到某处后，后台优先翻译该处之后的内容。
- 地址栏为 `#read/<任务 id>`，刷新后仍停留在原文档；按 Esc 返回。
- 预览只推送已完成的段落，不重建输出文件，不影响翻译速度。

### CC Switch

本机安装了 [CC Switch](https://github.com/farion1231/cc-switch) 时，「翻译服务」页会多出一组「CC Switch 当前生效」，直接使用其中 Claude、Codex（ChatGPT）、Gemini、Grok 当前选中的供应商：

- 以只读方式打开 `~/.cc-switch/cc-switch.db`（可用环境变量 `CC_SWITCH_DB` 指定），每次翻译时读取，Key 不会复制到本项目。
- 在 CC Switch 中切换供应商后，点击列表中的「刷新」生效。
- 地址和 Key 以 CC Switch 为准；模型、并发、提示词等可在此单独调整。
- Codex 默认使用 OpenAI Responses API，`wire_api = "chat"` 时才使用 Chat Completions；Grok Build 仅在 `api_backend = "responses"` 时使用 Responses API，其余使用 Chat Completions；Claude 使用 `ANTHROPIC_AUTH_TOKEN` 时按 Bearer 认证。
- 官方账号登录（OAuth）的配置没有 API Key，显示为不可用。

### 语言

源语言和目标语言均可选择，语言表（128 种，含文言文、粤语、东北话等）取自沉浸式翻译。

- 源语言默认「自动检测」：抽样检测文档语言，用于提示词中的 `{{from}}`，并匹配 `wyw2zh-CN` 这类按源语言生效的提示词。
- 已经是目标语言的段落不翻译（例如英文书中引用的中文，翻成中文时跳过）。简体与繁体互译不算同一种语言。
- 检测到文档语言与目标语言一致时，任务页会给出提示，对应插件的 sameLangCheck。
- 谷歌翻译按插件的代码映射转换语言（zh-HK→zh-TW、fil→tl 等）；不支持的语言（如文言文）会提示改用 AI 服务。
- 译文元素带 `lang` 属性；阿拉伯语、希伯来语等从右到左的语言加 `dir="rtl"`，PDF 中右对齐。

### 提示词

默认提示词和分段协议取自沉浸式翻译 1.33.3（`app/prompts.py`）：

- 按插件 langOverrides 的 `<from>2<to>` 规则选择提示词。简体中文、繁体中文、英语、日语、韩语、俄语、法语、西班牙语、葡萄牙语、文言文、东北话有专门的提示词，其他语言使用通用英文模板。
- 目标为简体、繁体、东北话和文言文到白话时，提示词要求标题、目录里带单位词的章节编号（Chapter 2、Volume II）使用中文数字，裸数字和带点的小节号（2、7.4、1.2.3）保留阿拉伯数字，同一术语只用一个译名。翻成中文时，标题和目录开头的「第2卷」改为「第二卷」；原文是 7.4、12 这样的编号而译文写成「七点四」「第十二章」的，改回原来的数字；正文以及「第25卷第1期」这类卷期保持原样。缓存中已有的旧标题会在下次翻译时一并改写。
- 多段批量翻译用 `[[p0]]`、`[[p1]]`… 标记分段，以 `[[source_end]]` 结尾，模型按标记返回；遗漏的段落单独补译。
- 书名或文档标题作为上下文填入 `{{title_prompt}}`。
- 自定义提示词可使用 `{{to}}`（目标语言）、`{{from}}`（源语言）、`{{text}}`（原文）、`{{title_prompt}}`，分段协议会自动附加。

配置保存在 `data/services.json`（权限 600），API Key 不会返回给前端。

译文缓存在 `data/cache.sqlite3`，缓存键包含翻译服务 id、供应商、模型、提示词、术语表、源语言和目标语言。配置相同时，同一段文字直接使用缓存；修改模型、提示词或术语表后，整篇按新配置重新翻译，改回原配置时仍命中原来的缓存。任务中途失败后重新提交，可从中断处继续。

## 网页翻译（Chrome 扩展）

`extension/` 目录里的浏览器扩展通过本服务翻译正在看的网页：按下快捷键，每段译文显示在原文下方。使用时本服务需要在运行。

1. 打开 `chrome://extensions`，开启开发者模式，点「加载已解压的扩展程序」，选择 `extension/` 目录。
2. 按 `Alt+T`（macOS 上是 Option+T），或点工具栏上的扩展按钮。第一次按开始翻译，之后再按隐藏、显示译文；请求失败后再按会重试。
3. 快捷键在 Chrome 的 `chrome://extensions/shortcuts` 页面修改（扩展不能自己设置）。扩展的设置页显示当前快捷键，有按钮跳到该页面；还可设置服务地址、翻译服务和语言。翻译服务是本服务上已启用的服务，Key、模型和提示词在本服务的页面上设置。

- 按页面版式分段：行内元素归入所在段落，空一行（`<br><br>`）另起一段。跳过代码块、表单控件、可编辑的内容（`contenteditable`）、标有 `translate="no"` 或 `notranslate` 的块，以及已经是目标语言的段落和只给读屏软件看的文字。句子里标为不翻译的文字（命令名等）在译文中原样保留。译文放在原文下方；在 flex、grid 横排和行内框（标签、按钮式链接）里则紧跟原文放在同一行，以免打乱版式。
- 设置页的「翻译范围」可选整个网页（默认）或只翻译正文。只翻译正文时，标出了正文的网页（`<main>` 或 `role="main"`）只翻译正文，正文里的导航和侧栏除外；没标出的网页翻译除页头、页脚、导航和侧栏以外的全部内容（文章或小节自己的页头、页脚算正文）。修改后对之后开始翻译的网页有效。
- 页面之后改动的文字（逐字输出的聊天回复、计数、单页应用替换的内容）在停止变化一秒后重新翻译，替换旧译文；同一处被替换超过十次（滚动的行情等）就不再翻译，保留原文。
- 译文沿用所在段落的字体，但带有标记，便于和网页原有的文字区分：浅蓝色底、左侧一条蓝色竖线（与原文同行的译文没有竖线）和单独的文字颜色，仅显示译文时也保留。用浅色还是深色配色，按每条译文背后实际的背景决定（祖先元素里最近的不透明背景），所以浅色页面上的深色页头、浅色浏览器里的深色网站都用深色配色；页面没有设置背景时，看页面的 `color-scheme` 和浏览器是否处于深色模式。在白色和深色背景上，文字对比度都在 9:1 以上（WCAG 要求 4.5:1）。
- 显示方式可选「双语对照」（默认）或「仅显示译文」，在设置页修改，或用快捷键「切换双语对照 / 仅显示译文」（默认没有分配按键，在 `chrome://extensions/shortcuts` 设置），已翻译的页面立即切换。仅显示译文时，已翻译段落的原文被隐藏（原文节点留在页面里，只是清空文字），图片、表单控件照常显示；隐藏译文就恢复原文。
- 只发送视口上下一屏内的段落，其余的随滚动翻译；页面之后加入的内容（无限滚动、单页应用）也会翻译。
- 译文保留链接和行内格式（粗体、斜体、下划线、删除线、行内代码、上下标、高亮）。这样的段落以 HTML 发送，只含这几种标签，每个标签带编号、不带属性。译文不会当作 HTML 插入页面：先在不执行脚本的独立文档里解析，再用 DOM 接口重建。与原文对得上的标签（按编号，没有编号按标签依次对应）换成原页面元素去掉 `id` 后的副本，`href` 等属性都来自页面，不来自模型；其他标签只留文字，脚本、图片等直接丢弃。没有格式的段落仍以纯文本发送和插入。
- 扩展只在按快捷键或点按钮时取得当前标签页的权限（`activeTab`）。安装时只能访问 `127.0.0.1` 和 `localhost`；在设置页连接其他机器上的服务时，浏览器才请求访问该地址（服务端要监听外部地址，并在 `ALLOWED_HOSTS` 里加入这个地址，连不上时设置页会说明原因）。http 地址不加密，页面文字以明文经过网络，请只在可信的网络里使用。页面文字只在按快捷键后，或在设为自动翻译的网站上（见下文），才发给所选的翻译服务。
- 网页译文和文档共用翻译缓存，但不保存为记录，也不生成文档术语表（每页要多一次请求）；服务里填写的术语表仍然生效。
- 扩展设置页显示缓存了多少条网页译文，可以一键清理（「清理网页翻译缓存」）。清理后，之后打开的网页会重新翻译，已经显示的译文不受影响；和文档共有的段落留给文档使用。加这个功能之前缓存的网页译文没有标记，清不掉，缓存满了会自动淘汰。接口是 `GET` / `DELETE /api/web/cache`。
- 接口是 `POST /api/web/translate`，请求 `{"texts": [...], "html": [...], "target_lang", "source_lang", "service_id", "title"}`，最多 50 段，每段最多 10000 字；`html` 与 `texts` 对齐，标出哪些是 HTML 片段，AI 翻译服务对这些段落使用 HTML 提示词，谷歌翻译使用 `format=html`；返回 `{"translations": [...], "detected_lang"}`，`null` 表示保留原文。和所有会改动数据的请求一样，来自其他网页的请求会被拒绝（见「已知限制」）。
- 扩展能访问的 iframe 随页面一起翻译（与页面同一网站的 iframe 总能访问，其他网站的要有该网站的权限），也随快捷键一起隐藏、显示；之后才加入的 iframe 在下次按快捷键时开始翻译。输入框的占位文字（`placeholder`）随页面翻译，提示文字（`title`）在鼠标悬停时才翻译，因为大多不会被看到。双语对照时属性同时显示两种文字（`原文 / 译文`，提示文字分两行）；隐藏译文就恢复原文；页面之后自己改过的值不再动。`alt`、`aria-label` 不翻译，它们不显示在页面上。
- 暂不支持：shadow DOM。Chrome 自己的页面、应用商店和内置 PDF 阅读器不能翻译，此时工具栏按钮显示 `×`。

### 翻译选中的文字

选中文字后点右键，选「翻译选中的文字」：译文显示在选区下方的小气泡里，靠近窗口底部时显示在上方。按 Esc 或点别处关闭。这个命令默认没有快捷键，可以在 `chrome://extensions/shortcuts` 设置。

- 选区的每一行作为一段翻译；超过 10000 字的行在句末切开，选区很长时每次请求发 50 段。
- 文本框里选中的文字也能翻译，但密码框、一次性验证码等存放机密的输入框除外，它们的内容不会发出。用快捷键时，从用户所在的框架里取选中的文字；iframe 里的也可以，只限扩展能进入的框架（凭 `activeTab` 只能进入和页面同源的框架）。

### 自动翻译的网站

在网页空白处点右键，选「总是翻译此网站」：浏览器会请求访问该网站的权限，之后这个网站的网页一打开就开始翻译，和按了快捷键一样；按快捷键仍可隐藏、显示译文。在这样的网站上，菜单项变成「不再自动翻译此网站」。扩展的设置页列出这些网站，每个都可以移除。

- 网站按主机名区分，包括 http 和 https；其他子域名算不同的网站。只翻译顶层页面，不翻译其中的框架。
- 扩展只有在这些网站上不按快捷键也能访问页面。移除网站会同时放弃该权限；在浏览器设置里撤销权限，也会停止自动翻译。
- 列表随浏览器账号同步（`chrome.storage.sync`），但权限要在每个浏览器上各自授予：在另一台电脑上，设置页会标出尚未授权的网站，在该网站上用同一个菜单项授权即可。

### Firefox

Firefox 128 及以上版本也能运行这个扩展，不过只在 Chrome 上测试过。Firefox 要用另一份 manifest：它的后台是 `background.scripts` 里列出的事件页面，而 Chrome 遇到这个字段会报警告。所以 `extension/` 是 Chrome 版，Firefox 版要用下面的命令生成到 `dist/firefox/`：

```bash
python3 scripts/build_firefox.py
```

然后打开 `about:debugging`，选「此 Firefox」，点「临时载入附加组件…」，选择 `dist/firefox/manifest.json`。扩展更新后要重新生成一次。临时附加组件在退出 Firefox 后会被移除，长期安装需要经 Mozilla 签名。快捷键在 `about:addons` 齿轮菜单的「管理扩展快捷键」里修改，Firefox 137 起设置页的按钮可以直接打开它。

扩展的图标画在 `extension/icons/icon.svg` 里。Chrome 的 manifest 只接受 PNG 图标，所以改了它之后要用 [librsvg](https://gitlab.gnome.org/GNOME/librsvg) 重新生成 PNG：

```bash
for s in 16 32 48 128; do rsvg-convert -w $s -h $s extension/icons/icon.svg -o extension/icons/icon-$s.png; done
```

## 各格式的处理方式

| 格式 | 做法 | 输出 |
| --- | --- | --- |
| Markdown | 按块切分，跳过代码块和 front matter，保留标题、列表、引用、表格的结构 | `.md` |
| EPUB | 按 OPF spine 找出正文，翻译最内层的块级元素，目录（nav / ncx）一并翻译；段落内的行内格式（加粗、斜体、链接、页码锚点）保留，其他资源原样打包 | `.epub` |
| MOBI / AZW3 | 先解包。KF8 格式直接取其中的 EPUB，旧的 MOBI7 先转成 XHTML 再拼成 EPUB，之后按 EPUB 流程翻译 | `.epub`；安装了 Calibre 时另输出一份原格式 |
| PDF | 提取文本块，擦除原文后在原位置写入译文；图、矢量图形和书签保留。详见下面的「PDF」一节 | 仅译文：原版式；双语：原文和译文左右并排 |
| Word（.docx） | 翻译正文、表格、文本框、页眉页脚、脚注和尾注中的段落。格式与段落其余部分不同的文字（粗体、斜体、链接）带标签发送，译文中格式落在对应的词上；图片、制表符、换行、脚注引用和域代码保留在原位置。样式、编号和文档包中的其他内容原样复制。参考文献部分保留原文 | `.docx`；双语：每段后面接一段译文，译文段不带列表编号 |
| HTML（.html、.htm、.xhtml） | 按 EPUB 章节的方式翻译最内层的块级元素，保留行内格式和链接；脚本、样式和代码块不动，页面标题一并翻译。按页面声明的编码读取 | 原格式，UTF-8 编码；双语：每个块后面接它的译文 |
| 字幕（.srt、.vtt、.ass、.ssa） | 每条字幕作为一段，各行合并后翻译；每行都以破折号开头的字幕（两人对话）逐行翻译。时间轴、序号、字幕设置、VTT 文件头和注释、ASS 样式、行首的特效标签和矢量绘图保留；文字中间的标签（VTT 的 class、行中的 ASS 特效）不进入译文。能识别 GBK、Big5、Windows-1252 等旧编码 | 原格式，UTF-8 编码，换行符与原文件相同；双语：原文各行下面接译文 |

### PDF

处理流程：用 PyMuPDF 提取文本块，按字形擦除需要重排的原文（不按矩形擦除，避免误删压在框边上的其他文字），再把译文写回原位置。放不下时依次处理：先向右扩展（仅限明显窄于页宽的块，且不覆盖右侧的文字和图），再压缩行距，最后缩小字号。

- **版心**：按全书正文长行的起止位置定出版心，奇偶页分开统计。版心外与正文同行、字号较小、沿同一条边对齐的短词是页边旁注。四个词以内、不成句的旁注是术语，保留原文；成句的旁注单独翻译，写回原处，左侧的旁注靠右对齐。正文不会因旁注断成几段。
- **分栏和阅读顺序**：两栏、三栏按栏边写入，不覆盖图和矢量图形。栏沟明确时先按栏从上到下阅读，跨栏标题和整表保持纵向位置。同一栏的段落跨页、左栏页尾接右栏页首时合并为一段，按满行排版，止于页码带上方。段落绕着图排时，夹在两半中间的图注不打断段落，译文在图旁的几行同样让开图和图注。
- **表格**：有横竖线的表、每格一块底色拼成的表（只有上下横线也算）和列缘对齐的短格子表，格子里的字一律保留原文，表注照常翻译。跨页合并段落时，表格仍挡在栏底，表头不会接到下一页的段首。算法框中的伪代码按一列的表处理，每行一格，逐行翻译，写回时不越出格子，不合并成段。整段正文不会被当成表。
- **公式**：行内公式是段落中的一个单元，译前收成占位符，译后从原页裁图，按行排版并贴回基线。贴回的公式只带自身的字形，拖选、复制时不会带出整页原文。正文字体中的希腊字母、数学符号，以及紧邻公式的罗马体数字和算子名并入同一占位符；`i-th` 这类序数留在正文中翻译。整行的行间公式保留原文；用正文字体排、带伸长大括号的分段式子也保留原文。
- **排版**：由排版器自行断行。汉字行两端对齐，标点不出现在行首；块内与正文不同的粗体、斜体、字号和文字颜色（蓝色的引文、交叉引用，彩色标出的字串）予以保留，跨行时下一行接着用；封面、题名页这类各行共用一条中线的页面，译文按这条中线居中，作者名下面小一号的单位单独成行；阿拉伯语、希伯来语等从右到左的语言右对齐。
- **保留原文**：以下内容不翻译：图内文字（包括矢量图、插图，以及 Figure N 图注上方到上一段正文之间的区域，其中用字形画出的节点标签、表和伪代码也在内。正文以「Figure 2.13 shows」开头的句子不算图注）；整块几乎都是等宽字体的内容（代码、照录的提示词和对话、例句，等宽字体按字体名或 PDF 的等宽标志认），以及底色上几乎全是等宽字的整片内容（码位表、代码框）；和全文不是同一种语言的段落（外文题记、引文、例句；分两列排的短条目合起来认）；语言学例句的逐词、逐语素对译，以及汉字下面一字一音节的拼音（下面的意译照翻）；重复的页眉、页脚和页码，包括版心以上、带页码或随小节变化的书眉。黑底白字的图注标签按原样贴回；图或表比正文宽、图注从页边起笔时，标签仍归图注，不当作旁注。目录条目只翻译标题：行尾的点线和页码不送翻，页码留在原位置，点线从页码前一直补到译文末尾，每条单独成段。落在近白底色上的正文和图注仍翻译，紧挨着图的图注、表注单独翻译；页末的脚注照常翻译，但不参与跨页合并。
- **点阵字**：旧版 Ghostscript 生成的 Type3 字体没有 Unicode 时，用 tesseract 识别字母后再翻译。这需要本机安装 tesseract（含英文语言包），未安装时任务会报错。
- **双语版**：原页和译文页左右并排在同一页上。

### PDF 版面模型（可选）

默认只用规则划分版面，不下载模型。如需让图表中的图例、没有图注的图、非 TeX 字体排版的行间公式也保留原文，可在「版面模型」页接入 YOLO 版面模型：

1. 安装运行环境：`.venv/bin/pip install onnxruntime`，然后重启服务。页面会显示是否安装成功。
2. 选择下载来源（Hugging Face、HF-Mirror、ModelScope），点「下载模型」，文件保存到 `data/models/`，下载完成后按校验值核对。已有模型文件时，也可以直接填写路径。
3. 勾选「翻译 PDF 时使用版面模型」并保存。可先点「测试模型」，在样例页上试运行。

使用的是 [DocLayout-YOLO DocStructBench 的 ONNX 版](https://huggingface.co/wybxc/DocLayout-YOLO-DocStructBench-onnx)（AGPL-3.0，约 75 MB），按其 title、figure、isolate_formula 等类别名识别。CPU 上每页推理约一秒多。模型框出的图和行间公式保留原文；规则判为正文的块，若模型框为标题或图注，则改按标题或图注处理。规则已识别的图内文字、编号标题不会被模型改动。未安装 onnxruntime、文件不存在或加载失败时，仅使用规则，翻译照常进行。

### PDF 公式检测模型（默认开启）

规则按字体识别行内公式。正文用 Times 等字体排版时，斜体变量和正文里的斜体词是同一种字体，x、P(y = 1) 这类式子常被拆开翻译。公式检测模型从页面图像里框出行内公式，框里的字整体做成占位符，按原样贴回译文。它在「版面模型」页下方单独设置，默认开启：

1. 运行环境同上，需要 onnxruntime。
2. 选择下载来源（Hugging Face、HF-Mirror），点「下载模型」，文件保存到 `data/models/`。模型文件不存在时只用规则。
3. 需要更快时把「输入尺寸」改成 768；不需要时取消勾选「翻译 PDF 时使用公式检测模型」。同一页上还可以改同时推理的页数和每页推理线程数，默认值按 CPU 核数算出。改完点保存。

使用的是 [Pix2Text MFD 1.5](https://huggingface.co/breezedeus/pix2text-mfd-1.5)（YOLO11m，约 80 MB），类别 embedding 是行内公式。模型卡标的是 MIT 许可，文件元数据标的是 AGPL-3.0。页面默认按 1024 的边长输入，也可以在页面上改成 768：分析版面快三成左右，单个字母的变量漏得多一些（36 篇论文上 97.4% 对 99.0%）。模型在后台线程里提前推后面的页，同时读当前页：4 核以上默认两页同时推理，各用一份模型、平分 CPU 核，推理线程等活时不空转，把核让给读页面的线程。在 6 核 CPU 上，这样比一页用 4 个线程快两成左右。页面图像只补灰边到 32 的倍数，不补成正方形，信纸大小的页少算两成多的像素，两个模型都快两成左右。1024 时分析版面每页多花约 0.8 秒，768 时约 0.4 秒。同时推理的页数和线程数只影响速度，分析结果不变。框尾的逗号、句号留在正文里，只框着数字的框不算公式。模型框成行间公式（isolated）的块保留原文，用正文字体排的行间公式（perplexity(T) = P(red red blue) 这类）不再被译成中文；框里成句的说明（含三个以上冠词、介词等虚词，如 (where c is the correct class)）和标题照翻。分段和角色仍按规则和版面模型。在 36 篇 arXiv 论文上，行内公式识别正确的比例（公式整体做成占位符，外面最多漏下数字、单位）从 78.4% 提高到 99.0%，其中非 TeX 字体的论文从 67.2% 提高到 98.5%。

### 模型的 int8 版（默认使用）

int8 版把模型的权重和中间结果换成 8 位整数。公式检测模型推理快一倍左右，版面模型快三成左右，分析结果都和原模型基本相同。int8 文件要在本机生成一次，两个模型各自生成：

1. 安装 onnx：`.venv/bin/pip install onnx`，然后重启服务。onnx 只在生成时用，翻译时不需要。
2. 下载好模型后，在「版面模型」页对应的标签下点「生成 int8 模型」。程序从翻译记录里的 PDF 随机抽 64 页校准，没有翻译过 PDF 时用一张自造的样例页。6 核 CPU 上约三分钟，生成的文件约 20 MB，放在原模型旁边，文件名多一个 `.int8`（如 `pix2text-mfd-1.5.int8.onnx`）。生成完在几页上和原模型比框出的框数，少了一半以上就不保存。同一时间只生成一个模型。
3. 「精度」默认选 int8：int8 文件存在时用它，不存在时用原模型。选 fp32 一直用原模型。

量化时检测头的解码部分留 fp32，权重只用 7 位，中间结果的范围取各页的滑动平均，原因写在 `app/quantize.py` 开头。在 36 篇 arXiv 论文上，用翻译过的 17 个 PDF（教材、论文）校准：公式检测模型的行内公式识别正确的比例和原模型一样是 98.9%，分段不变，6 核 CPU 上每页推理从 1.11 秒降到 0.56 秒；版面模型的分段和原模型相同，框和原模型的对上 98.6%，每页推理从 1.05 秒降到 0.66 秒。评测方法见 `eval/README.zh-CN.md`。换了精度后，旧任务重新分析时框缓存对不上，要重新推理一遍。

### 参考文献

参考文献章节（Bibliography / References / Works Cited / Further Reading / Endnotes / 参考文献，含带冒号或编号的标题）保留原文，不翻译；标题本身仍翻译，预览中标注为跳过。

- **EPUB**：按标题层级和 `epub:type` 识别，可跨 spine 文件延续。同级或更高的标题、平铺文档中的下一章会结束该节，小标题不会。文件名主体即为参考文献的，整篇跳过。
- **PDF**：标题字号高于正文（或加粗），且后面紧跟引文条目时进入。引文条目的特征是题名后带 `[J].` / `[M].` 和年份，或编号条目带出版社（年份、出版社可在下一行）；正文中零散出现的年份、出版社不算。遇到字号接近或仍明显高于正文的加粗标题时退出；比参考文献标题更小的 Books、Articles 等小标题留在节内。没有标题的参考文献（书的章末常紧接着习题排）按条目认：一连串同字号、以「姓, 名缩写.」起头的作者-年份条目保留原文，中间的续行一并保留。
- 跳过的 PDF 条目保留在原页，不被擦除重排，悬挂缩进和行尾断词保持原样；与某条引文完全相同的正文段落仍会翻译。

## 已知限制

- Word 文档中行内内容控件、批注、图表和 SmartArt 里的文字不翻译。一句话跨几条字幕时按条分别翻译。译好的 HTML 页面仍按原来的相对路径引用图片和样式，放在原页面的文件旁边才能显示。
- 暂不支持需要 OCR 的扫描版 PDF。没有表线、列缘也不对齐的表认不出来，其中的字仍会翻译。栏沟不明显时，阅读顺序可能与分栏不符。以英文大写字母开头的换行仍各自成段。
- 服务没有鉴权，仅适合在本机使用（默认绑定 127.0.0.1）。但同一浏览器里打开的网页仍能向它发请求，所以会改动数据的请求（POST、PUT、PATCH、DELETE）只接受来自本服务自己的页面、浏览器扩展，以及不带 `Origin` 头的工具（curl、脚本）；其他 `Origin` 一律返回 403。否则任何网站都能在读不到结果的情况下暂停、删除任务，或消耗翻译额度。读取请求不检查：没有 CORS 头，其他网页读不到结果。
